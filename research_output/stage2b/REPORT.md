# Stage 2B report — historical realized volatility (RV) of NIFTY 50

Scope: realized volatility **only**. No IV-vs-RV comparison, no options data, no strategy. Built independently of the
options strike universe: it reads the spot file and calendar evidence only (the Stage 2A strike-selection finding for
expiries beyond 14 days is untouched and still stands). Nothing is committed (per instruction); outputs are regenerated by the
commands in §9. Source files are read-only.

## 1. Inputs and conventions
| item | value |
|---|---|
| spot file | `data/hist1m/NIFTY50_1m.parquet` — columns `ts` (int64 epoch seconds, **UTC**), `open`, `high`, `low`, `close`; no volume. 467,063 records, 2021-09-16 → 2026-09-30 |
| timestamp meaning | **bar start**. IST = UTC+05:30 (fixed, no DST). Session date = IST date of `ts` |
| evidence for "bar start" | in all 1,241 regular sessions the last bar starts 15:29 (index closes 15:30) and 1,239 start 09:15; a bar-close convention would put the last bar at 15:30 and the first at 09:16. Consistent with the Phase 1/2A audit of the option files |
| regular session | bars 09:15…15:29 = **375** bars; the 15:29 bar's close is known at 15:30:00 (the observation time of every rolling row) |
| spot vs F&O close | spot index closes 15:30 on every day, including after F&O moved to 15:40 (2026-08-03). The F&O 15:40 convention is **not** used here |
| calendar | layered (`session_calendar.py`): weekend → no; 2021-09-01…2026-09-25 → date must have a `data/participant_oi` file (independent of the spot file); later dates → repository `market_calendar.is_trading_day`. The repository holiday list only covers **2026**; it agrees with the spot data on 184 of the 185 sessions of 2026; the 185th is the 2026-02-01 Sunday special session, which it (rightly) does not list, and no repo trading day lacks spot data |

## 2. Definitions (all log returns; variance = sum of squared returns)
* **Intraday 1-minute returns:** `r0 = ln(close0/open0)`, `r_i = ln(close_i/close_{i-1})` for i = 1..374 when **both** bars are valid. A complete session has 375
  returns and `Σ r_i = ln(C/O)` (verified to 1e-12). A missing/invalid bar k removes `r_k` and `r_{k+1}`; nothing is filled and no return spans a gap.
  Overnight moves are never one-minute returns.
* **Intraday variance** `V_intraday = Σ r_i²` per session — a *sum*, so there is **no minutes-per-day factor** to get wrong.
* **Overnight** `r_on = ln(Open_t / Close_{t-1})`, **close-to-close** `r_cc = ln(C_t / C_{t-1})` with `C_{t-1}` the 15:29 close of the previous *regular* session
  in the chain; invalid if either price is missing or a regular session lies between (`previous_regular_session_missing`). `overnight_calendar_days` shows
  weekends/holidays (938 one-day, 38 two-day, 232 three-day, 30 four-day, 2 five-day gaps).
* **Hybrid** `V_hyb = r_on² + V_intraday` (the high-frequency, overnight-inclusive analogue of `r_cc²`).
* **Annualization:** vol % = `100·√(A · mean V)`, **A = 252 sessions/year** (a convention, configurable). Vol is in **percentage points**; mean variance, sums and return counts are
  kept so every number is reproducible. Observed sessions per year: 247/245/245/247 (2022-2025), mean 246 → using 252 inflates vol by **1.2 %** relative (×0.988 would match 246).
* **Intraday-only RV excludes overnight movement** and is *not* comparable with close-to-close RV (overnight is 43 % of hybrid variance on average — §5).
* **Rolling windows (5/10/20):** last N sessions of the regular chain ending at the observation session; observation time 15:30 IST of that day; later data never used.
  `strict` (primary): all N observations valid, otherwise **no value** (never silently shortened). `coverage_qualified` (separately labelled): needs ≥ 80 % of the N sessions valid;
  a session counts only if ≥ 98 % of its returns are valid **and** the first/last 15 bars are present; incomplete sessions are rescaled `V·375/n`; `n_obs` always reported.
  Close-to-close over N sessions = N returns from N+1 consecutive valid closes.
* **Special/incomplete sessions:** weekend, Muhurat/short and off-hours sessions are *not in the chain* — they neither count toward N nor break it. A regular session with missing minutes
  stays in the chain but is invalid for strict intraday/hybrid (so it blocks the N windows that contain it); a missing regular session would be an invalid link.

## 5. Validation on real data
**Two independent calculations** (`validation/independent_rv_check.py`; neither imports `optionsengine`): **A** pure-Python streaming loops (math.log, own chain rule using participant-OI dates), **B** pandas
groupby + reindex-to-the-375-minute-grid. Both implement the written definitions, not the module's code.
* Per session (1,241 regular): A vs module — return counts identical (0 mismatches), `Σr²` max difference **1.0e-16**, close-to-close and overnight max difference **1.0e-16**, validity identical.
  B vs module — **1 session differs: 2023-09-21**, where B (no OHLC screening) keeps the 09:15 bar whose open lies above its high (return-count 375 vs 374; `Σr²` difference 4.9e-7); the module and A exclude it by design.
* Rolling (all 9 measure×window combinations, strict): max difference module-vs-A **≤ 2.1e-14 vol pts**, module-vs-B ≤ 1.4e-14 on windows both compute; the only availability disagreements (5/10/20 windows for N = 5/10/20, intraday & hybrid) are the windows containing 2023-09-21 under B.
  *Reconciliation note:* my first A used a crude "gap ≤ 4 calendar days" chain rule and disagreed on 2021-11-08 and 2022-04-18 (five-day holiday+weekend spans, e.g. Good Friday week); replacing it with a participant-OI-based rule removed the disagreement — the module's calendar logic was right, A's heuristic was not.
* Representative session 2026-09-30: first five 1-minute returns 1.2133e-4, 3.7271e-4, 3.0203e-4, 2.3803e-4, 6.2788e-4; 375 returns, `Σr² = 3.4581414935e-5` → intraday vol `100·√(252·Σr²)` = **9.335158 %**; close-to-close −0.00422396, overnight −0.00225644 (A and module identical).
* **No look-ahead on real data** (`validation/lookahead_check_rv.py`): re-running with the file truncated at 15:30 of 25 random sessions reproduces that session's daily row and all 13-column rolling rows exactly (0 mismatches).

**Sampling convention** (`validation/sampling_and_annualization_check.py`, 1,237 complete sessions): mean daily intraday variance by sampling interval relative to 1-minute: 2-min 1.012, 3-min 1.014, 5-min 1.022, 10-min 1.013, 15-min 1.047, 25-min 0.994, 75-min 1.023, one open→close return 1.114.
No sign of microstructure noise inflating 1-minute RV; if anything coarser sampling is 1-2 % *higher* (mild positive return autocorrelation; the single open→close return is 11 % higher), so 1-minute RV is, if anything, slightly low.
Overnight + intraday vs the daily second moment: mean hybrid / mean r_cc² = **1.02** overall (by year 0.92-1.20); intraday-only / r_cc² = 0.58 — confirming intraday-only RV is not a substitute for close-to-close RV.

**Results before vs after the quality exclusions** (`validation/quality_exclusion_comparison.py`): a naive calculation (returns between consecutive *records*, every date with bars, windows over all dates) vs the module —
daily intraday vol: median +0.73 vol pts, p95 |diff| 8.5, max 38 (the naive series turns the previous-close→open overnight gap into a one-minute return on every session; e.g. 2026-04-08: overnight +3.09 %, module intraday vol 11.7 % vs naive ≈ 49.7 %);
14 dates the module excludes (6 weekend, 4 incomplete regular, 2 short, 2 off-hours) would have produced naive "vols" of 3.5-39 %; rolling 20-session RV: where both exist the naive value is higher by a median 1.84 vol pts (p95 6.0, max 11.7) and the naive method gives a number for 80 windows that strict correctly leaves empty.

**Sensitivity to data-quality thresholds** (`sensitivity.csv`, N = 20 intraday coverage-qualified, window fraction 0.8): the coverage threshold only changes *which* sessions are admitted, not their values.
| min session coverage | edge guard | sessions admitted (of 1,241) | windows with a value | fully complete windows |
|---|---|---|---|---|
| 100 % (= strict) | — | 1,237 | 98.47 % | 92.02 % |
| 99 % | 15 min / off | 1,238 / 1,239 | 98.47 % | 93.63 / 95.25 % |
| 98 % … 80 % | 15 min | 1,239 | 98.47 % | 95.25 % |
| 98 % … 80 % | off | 1,241 | 98.47 % | 98.47 % |
The edge guard (first/last 15 bars present) is a **data-driven rule**: `validation/missing_bar_stress_test.py` deletes bars from 400 complete real sessions and measures the error of the `V·375/n` rescaling on session variance —
scattered or mid-session gaps: median error 0.5-1.2 % at 99-98 % coverage, 1.8-2.6 % at 95 %, 2.7-4.9 % at 90 % (p95 up to 8 %, 13 % for gaps at the close); **a gap at the open: mean bias −9.5 % (99 % coverage) to −19.8 % (90 %), worst −88 %** — the opening minutes carry far more variance than average.
The two real sessions the guard excludes are exactly 2021-12-20 and 2023-09-21 (open bars missing); the two it admits are rescaled by +0.54 % and +1.08 % (variance). Annualization sensitivity: A = 246 / 248 / 250 / 252 scales every RV by ×0.988 / 0.992 / 0.996 / 1.

## 7. Limitations and unresolved uncertainty
1. **Calendar:** the repository has no holiday list before 2026. For 2021-2025 the calendar rests on `participant_oi` dates (trading dates, including Muhurat evenings), which matched the spot data exactly except six weekend special sessions; a date missing from *both* would be indistinguishable from a holiday (none observed).
2. **Timestamp convention** (bar start) is inferred from first/last bar times and the index close at 15:30; no vendor metadata states it.
3. **Unexplained:** 2021-11-04 (Diwali) has 43 bars at 14:47-15:29 in addition to the 60-bar evening session; classified special_short. Pre-open bars 09:08-09:14 on 2026-09-07/08/09 are treated as outside the regular window (indicative-index prints assumed).
4. **Three full-length special weekend sessions** (2024-01-20, 2025-02-01 Budget Saturday, 2026-02-01 Budget Sunday: 375 bars each) are excluded from the chain and from intraday windows; their price moves are inside the neighbouring Friday→Monday close-to-close return, but their intraday variance is not counted anywhere.
5. Close-to-close and hybrid returns across weekends/holidays contain 2-5 calendar days of overnight movement; they are per-**session** variances annualized by sessions, not by calendar time (relevant when Stage 2C aligns with IV).
6. 252-day annualization is a convention (observed 246): +1.2 % relative on every vol. 1-minute RV assumes bars are index prints at minute ends; the vendor's bar construction is not documented.
7. Single-session `*_single_day` vols are one-observation estimates (very noisy) — use the rolling windows.
